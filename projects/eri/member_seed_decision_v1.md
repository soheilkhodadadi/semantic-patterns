# ERI Member Seed Decision V1

## Decision

Current status:
- staged placeholder, not a true local workspace member yet

## Why

ERI is strategically important, but it does not yet have the same local maturity as AI-washing.

Current pressures suggest caution:
- member boundary is still forming
- private and partner-sensitive materials may dominate early inputs
- there is not yet a stable local code stack to seed as a real member package

## Recommendation

Treat ERI as:
- a planned future project member
- initially supported by private-local materials and, if needed later, staged path-dependent intake

Do not rush it into a local buildable member until:
- the project-local source boundary is explicit
- the shared-vs-project split is clearer
- the public-safe tracked structure is ready to mean something real

## Trigger for promotion

Promote ERI from staged placeholder to real member seed when:
- there is a stable public-safe README and scope note
- the first local code or benchmark assets are ready
- a real member mapping note exists
- local-private and tracked boundaries are explicit

## Bottom line

ERI should stay planned and staged for now.
That keeps the member model honest and avoids seeding a package shell before the project has real local substance.
