# ERI Pilot Charter V1

## Purpose

This charter activates `ERI` as a small real project member rather than a pure
placeholder.

The aim is not full implementation.
The aim is to create a credible pilot lane that can support early research work,
interviews, and later roadmap design.

## Pilot goal

Build a minimal ERI pilot that demonstrates:
- a usable project boundary
- an initial corpus and taxonomy
- a reproducible scoring or benchmarking workflow
- one concrete pilot output

## Current basis

This charter is derived from:
- `projects/eri/member_seed_decision_v1.md`
- `docs/projects/eri/adapter_framing_v1.md`
- the ERI proposal document provided by the user

The proposal evidence currently points to an ERI pilot built around:
- use-cases and data architecture
- corpus v1
- reliability taxonomy and rubric
- labeled set v1 with IRR/QA/adjudication
- baseline scoring and validation

## Pilot scope

### In scope

- define the pilot use-case clearly
- assemble a small initial corpus
- define a reliability or scoring taxonomy
- produce one labeled mini-set
- run one baseline benchmarking or scoring pass
- write one short project-facing diagnostic brief

### Out of scope

- full-scale production deployment
- large shared-package extraction
- multi-year roadmap complexity
- pretending the project is more mature than it is

## Proposed first deliverables

1. ERI pilot framing note
2. corpus/sample v0 definition
3. taxonomy/rubric v0
4. labeled mini-set with QA notes
5. baseline scoring or benchmarking brief

## Suggested first technical shape

Recommended starting shape:
- one small input sample
- one pilot notebook or script
- one benchmark or scoring output
- one short interpretation note

This is enough to move ERI from placeholder to pilot.

## Success criteria

The pilot is successful if, by the end of the first round, ERI has:
- a clearly stated use-case
- a small but real corpus
- an explicit taxonomy or scoring rubric
- one reproducible scoring or benchmark artifact
- one short write-up of what the next full roadmap should be

## Planning posture

Recommended posture:
- keep ERI planning project-scoped
- do not force it into the giant AI-washing roadmap model
- only create a heavier roadmap once the pilot proves real execution pressure

## Bottom line

ERI does not need a big system next.
It needs a small, honest, research-grade pilot that makes the member real.
