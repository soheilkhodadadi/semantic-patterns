# Monthly Reporting Workflow V1

Purpose:
- keep supervisors and other project stakeholders updated without waiting for a full paper refresh
- make reporting a repeatable part of the delivery phase rather than an ad hoc scramble

## Folder layout

Markdown sources:
- `output/paper/reports/YYYY-MM/`

Word outputs:
- `output/doc/reports/YYYY-MM/`

Recommended files each month:
- `executive_update_YYYY-MM_v1.md`
- `detailed_update_YYYY-MM_v1.md`
- `attachments_manifest_YYYY-MM_v1.md`

## Content guidance

### Executive update

Use for:
- short high-level status
- what changed materially
- what the next gate is

Target length:
- roughly one page in Word

### Detailed update

Use for:
- data / methodology progress
- blockers resolved
- results that are informative enough to summarize
- next-step empirical plan

Target length:
- one to two pages in Word

### Attachments manifest

Use for:
- canonical file paths to the actual artifacts
- avoid duplicating large data files into the report folder unless there is a real distribution need

## Cadence

Recommended checkpoints:
1. major infrastructure or sample-definition change
2. first interpretable result on a new main-text table
3. delivery packet refresh
